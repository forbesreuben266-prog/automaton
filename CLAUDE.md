# Working preferences

## Responses
- Keep answers concise (about 150–250 words unless more detail is requested).
- Lead with the result, then key risks, then the next action.
- Use short bullet points and compact tables.
- Don't repeat earlier explanations, requirements or test details.
- Always include critical security warnings, even when being brief.
- Ask only for the specific approval needed to proceed.

## Hard limits (need explicit approval each time)
- No deploying, launching Automaton, provisioning servers or creating accounts.
- No creating or funding wallets, buying credits, configuring paid API keys,
  or placing trades.
- Don't commit or push until the user has reviewed the diff.
